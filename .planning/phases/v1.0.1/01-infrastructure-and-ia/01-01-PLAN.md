<task type="auto">
  <name>Task 1: Install VitePress and create site configuration</name>
  <files>
    package.json
    docs/.vitepress/config.mts
    docs/index.md
  </files>
  <action>
1. Install VitePress as a devDependency:
   ```bash
   npm install -D vitepress@latest
   ```
   Note: Use `vitepress@latest` (VitePress v2 is now stable). After install, verify the installed version in package.json and pin to the exact version installed (e.g., `"vitepress": "2.x.x"` not `"^2.x.x"`) to avoid unintended upgrades.

2. Add scripts to the root `package.json`:
   ```json
   "scripts": {
     "docs:dev": "vitepress dev docs",
     "docs:build": "vitepress build docs",
     "docs:preview": "vitepress preview docs"
   }
   ```

3. Create `docs/.vitepress/config.mts` with:
   - `title: 'VIT'`
   - `description: 'Phase-based project execution framework for Claude Code'`
   - `base: '/vit-cc/'` — CRITICAL: both leading and trailing slashes required for GitHub Pages
   - `cleanUrls: false` — GitHub Pages does not support clean URL routing natively; accept .html extension URLs rather than risk broken direct links
   - `themeConfig.search.provider: 'local'` with custom `_render` function to handle frontmatter titles in search index (see Pitfall 6 in research):
     ```typescript
     search: {
       provider: 'local',
       options: {
         async _render(src, env, md) {
           const html = await md.renderAsync(src, env)
           if (env.frontmatter?.title)
             return (await md.renderAsync(`# ${env.frontmatter.title}`)) + html
           return html
         }
       }
     }
     ```
   - `themeConfig.nav` with 6 entries: Get Started, Concepts, Commands, Agents, Guides, GitHub (external link to https://github.com/LeVarez/vit-cc)
   - `themeConfig.socialLinks` with GitHub link
   - `themeConfig.editLink` with pattern pointing to GitHub repo `docs/` directory
   - Empty `themeConfig.sidebar` object (placeholder — will be populated in plan 01-02)
   - `ignoreDeadLinks: true` — TEMPORARY for scaffolding; will be removed before first content PR in Phase 02

4. Create a minimal `docs/index.md` so the dev server has something to render:
   ```markdown
   ---
   layout: home
   ---
   # VIT Documentation
   Site under construction.
   ```
   This is a placeholder — the real homepage is created in plan 01-02.

5. Verify: Run `npm run docs:dev` and confirm the site serves without errors. Run `npm run docs:build` and confirm the build succeeds.

  </verify>

<task type="auto">
  <name>Task 2: Create GitHub Actions deployment workflow</name>
  <files>
    .github/workflows/deploy-docs.yml
  </files>
  <action>
1. Create `.github/workflows/deploy-docs.yml` following the official VitePress GitHub Pages deployment guide.

2. Key configuration:
   - **Trigger:** `push` to `main` branch, filtered to `paths: ['docs/**']` so code-only commits do not trigger a docs deployment
   - **Permissions:** `contents: read`, `pages: write`, `id-token: write`
   - **Concurrency:** group `pages`, cancel-in-progress `false`
   - **Environment:** `github-pages` with URL output
   - **Steps:**
     a. Checkout repo
     b. Setup Node.js (version 20)
     c. Install dependencies (`npm ci`)
     d. Build VitePress site (`npm run docs:build`)
     e. Upload artifact using `actions/upload-pages-artifact@v3` pointing to `docs/.vitepress/dist`
     f. Deploy using `actions/deploy-pages@v4`

3. Important: Do NOT enable any HTML minification steps — VitePress uses Vue hydration markers in HTML comments that minifiers break (Pitfall 7).

4. Reference the existing `phase-ci.yml` for the project's GitHub Actions conventions (Node version, checkout action version, etc.) and follow the same patterns.
  </action>
  <verify>
    Validate YAML syntax: `python3 -c "import yaml; yaml.safe_load(open('.github/workflows/deploy-docs.yml'))"` — must not raise an error.
    Verify the workflow file contains: `paths: ['docs/**']`, `actions/deploy-pages`, `npm run docs:build`, and `docs/.vitepress/dist`.
  </verify>
  <done>
    deploy-docs.yml exists, has valid YAML, triggers only on docs changes, builds VitePress, and deploys to GitHub Pages.
  </done>
