  <action>
  In the verify-work command (`.claude/commands/vit/verify-work.md` and `files/commands/vit/verify-work.md`), add PR promotion logic that runs AFTER posting the UAT comment on the GitHub feature issue (step 8) and BEFORE step 9 (issue diagnosis).

  Add a new step **8.5: Promote PR on Route A**:

  ```
  8.5. **Promote PR on Route A**

     Only promote if ALL tests passed (Route A — all pass, more phases OR Route B — all pass, last phase).

     **Check gh availability:**
     ```bash
     gh --version 2>/dev/null && GH_AVAILABLE=true || GH_AVAILABLE=false
     ```

     If `GH_AVAILABLE=false`:
     - Log: `[PR promotion skipped — gh not available]`
     - Continue (non-blocking)

     If `GH_AVAILABLE=true`:

     **Look up PR number from STATE.md:**
     ```bash
     PR_ENTRY=$(grep "| ${MILESTONE}/${PHASE_NUM} " .planning/STATE.md 2>/dev/null | grep -o 'pr#[0-9]*' | head -1)
     if [ -z "$PR_ENTRY" ]; then
       PR_ENTRY=$(grep "| ${PHASE_NUM} " .planning/STATE.md 2>/dev/null | grep -o 'pr#[0-9]*' | head -1)
     fi
     PR_NUM=$(echo "$PR_ENTRY" | grep -o '[0-9]*')
     ```

     If `PR_NUM` is empty or PR_ENTRY is `pr:skipped` or `—`:
     - Log: `No draft PR found for this phase — skipping promotion`
     - Continue

     **Promote draft to ready-for-review:**
     ```bash
     gh pr ready $PR_NUM 2>/dev/null && PR_PROMOTED=true || PR_PROMOTED=false
     ```

     If `PR_PROMOTED=true`:
     - Log: `PR #$PR_NUM promoted to ready-for-review`
     - Update STATE.md: change `pr#$PR_NUM` to `pr#$PR_NUM(ready)` in the PR column for this phase row
       ```bash
       sed -i '' "s/pr#${PR_NUM}/pr#${PR_NUM}(ready)/" .planning/STATE.md
       ```

     If `PR_PROMOTED=false`:
     - Log: `[PR promotion failed — PR #$PR_NUM may already be ready or closed]`
     - Continue (non-blocking)
  ```

  **Route gating logic:** This step ONLY runs when the UAT outcome is "all pass" (Routes A or B). The step must check the UAT result before attempting promotion. If issues were found (Routes C or D), skip this step entirely — the PR stays as draft.

  Specifically, add a guard at the top of step 8.5:
  ```
  If issues > 0 (Route C or D): Skip PR promotion entirely. PR remains draft.
  ```

  **Where to place this in the existing flow:**
  - The verify-work command currently has steps 0-9 in `<process>`.
  - Step 8 posts the UAT comment to GitHub.
  - Step 9 diagnoses issues if any found.
  - Insert step 8.5 between steps 8 and 9.
  - The step must be clearly gated: only runs on Route A/B (all tests pass).

  IMPORTANT:
  - Use `gh pr ready $PR_NUM` (not `gh pr review --approve` which would fail with 422).
  - Only promote on Routes A/B (all pass). Routes C/D leave PR as draft.
  - Graceful failure: if gh unavailable or promotion fails, log one line and continue (PRL-06).
  - Update STATE.md from `pr#N` to `pr#N(ready)` after successful promotion.
  - Both `.claude/` and `files/` copies must be exactly identical after edits.
