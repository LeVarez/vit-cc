```
# Core Concepts

One-paragraph overview: VIT organizes work into a hierarchy — milestones contain phases, phases contain plans, plans contain tasks. Commands drive the lifecycle. Agents do the work. State persists across sessions.

## The VIT Hierarchy

Mermaid diagram showing:
- Milestone → Phase (1:many)
- Phase → Plan (1:many)
- Plan → Task (1:many)
- Plan → Wave (grouping for parallel execution)
- Phase → Agents (spawned by commands)

Use `graph TD` with clear labels. Keep it focused on the hierarchy — do NOT show agent spawn relationships (that's Phase 02 scope).

## Milestones
- What a milestone is: a version-scoped unit of work (e.g., v1.0, v1.1)
- Contains multiple phases executed sequentially
- Has a goal statement and requirements
- Lifecycle: new-milestone → phases → audit → complete-milestone

## Phases
- What a phase is: a focused unit of work within a milestone
- Has a goal, success criteria, and requirements
- Produces code on a feature branch
- Lifecycle: plan-phase → execute-phase → verify-work

## Plans
- What a plan is: an executable prompt with 2-3 tasks
- Grouped into waves for parallel execution
- Has frontmatter (dependencies, files_modified, must_haves)
- Created by vit-planner agent during plan-phase

## Tasks
- What a task is: a single unit of work within a plan
- Types: auto (Claude does it), checkpoint (pauses for human)
- Each task has: files, action, verify, done
- Produces atomic commits

## Waves
- What a wave is: a group of plans that run in parallel
- Wave 1 runs first; Wave 2 starts after Wave 1 completes
- Waves maximize parallelism while respecting dependencies

## Agents
- What agents are: specialist Claude instances spawned by commands
- They are spawned, not invoked directly — commands orchestrate them
- Each agent has a specific role (planner, executor, verifier, etc.)
- Brief list of key agents and what they do (link to full agent reference in Phase 02)

## State
- How VIT persists state: `.planning/` folder with STATE.md, ROADMAP.md, PLAN.md files
- State survives context resets — every session reads STATE.md to know where to resume
- /vit:pause-work and /vit:resume-work handle mid-phase context boundaries

## See also
- [Getting Started](getting-started.md) — hands-on tutorial
- [Glossary](glossary.md) — term definitions
```

**Writing rules:**
- Explanation-oriented: explain WHY and HOW things relate, not step-by-step instructions
- No numbered steps (that's tutorial/how-to territory)
- Use present tense ("A phase contains plans" not "A phase will contain plans")
- Keep each section to 3-8 sentences. This is a concepts page, not exhaustive documentation.
- The Mermaid diagram must be valid GitHub-renderable Mermaid (fenced code block with `mermaid` language tag)
- Total page: 120-180 lines
