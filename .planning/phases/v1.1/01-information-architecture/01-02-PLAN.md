**Structure:**

```
# Getting Started

Brief one-liner: "This guide walks you through installing VIT and running your first complete phase."

## Prerequisites
- Node.js (version 18+)
- Claude Code CLI installed and authenticated
- A project directory (new or existing)

## Step 1: Install VIT
- Command: `npx vit-claude`
- What happens: copies framework files into `.claude/` directory
- What you get: agents, commands, hooks, templates
- Optional: GitHub CI workflow (say yes if you use GitHub)
- Time estimate: ~1 minute

## Step 2: Start a new project
- Command: `/vit:new-project`
- What happens: Claude asks about your project — goals, tech stack, constraints, timeline
- Answer the questions honestly — VIT uses these to build your planning documents
- What you get: `.planning/PROJECT.md`, `.planning/ROADMAP.md`, `.planning/STATE.md`
- Time estimate: 2-5 minutes

## Step 3: Plan your first phase
- Command: `/vit:plan-phase 1`
- What happens: VIT researches the phase domain, creates executable plans with task breakdown, then verifies plans against phase goals
- What you get: `PLAN.md` files in `.planning/phases/` with tasks, dependencies, and verification criteria
- Time estimate: 3-8 minutes

## Step 4: Execute the phase
- Command: `/vit:execute-phase 1`
- What happens: VIT executes plans wave by wave — parallel where possible, sequential where needed. Each task produces atomic commits on a feature branch.
- What you get: working code on a feature branch, a draft PR (if GitHub enabled), updated STATE.md
- Time estimate: varies by phase complexity

## Step 5: Verify your work
- Command: `/vit:verify-work 1`
- What happens: VIT checks the phase goals against what was built, runs goal-backward verification
- What you get: VERIFICATION.md report. If everything passes, the PR is promoted from draft to ready-for-review.
- Time estimate: 1-3 minutes

## What's next
- [Core Concepts](core-concepts.md) — understand the milestone → phase → plan → task hierarchy
- [Glossary](glossary.md) — look up any VIT-specific term
- [Commands reference](../../README.md#commands-reference) — full list of all 29 slash commands
```

**Writing rules:**
- Every step starts with the exact command to run (in a code block)
- Follow the command with "What happens" (1-2 sentences describing what the user will see)
- Follow with "What you get" (list of outputs/artifacts)
- Include a rough time estimate for each step
- Do NOT explain WHY VIT works this way — that belongs in core-concepts.md
- Do NOT define terms — that belongs in glossary.md
- Use second person ("you") throughout
- Keep the total page under 150 lines
