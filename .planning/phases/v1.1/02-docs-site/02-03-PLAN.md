- `files/commands/vit/plan-phase.md` (use as walkthrough example)
- `files/commands/vit/execute-phase.md` (complex orchestrator example)
- `files/commands/vit/new-project.md` (simple command example)
- Several other command files to identify common patterns

Write a comprehensive guide covering:
1. **File Location** — Commands live in `files/commands/vit/`. The filename becomes the command name (e.g., `plan-phase.md` -> `/vit:plan-phase`).
2. **Frontmatter Schema** — Document all frontmatter fields: `name`, `description`, `version`, `tools` (list of tools the command can use), and any other fields present. Show a complete example.
3. **Process Sections** — Commands use XML `<step>` or numbered sections to define their workflow. Explain the pattern: each step has a name, what it does, and what it produces.
4. **Orchestrator -> Workflow References** — Commands reference workflows via `@` syntax. Explain how a command like execute-phase references execute-phase.md workflow. Show how the command is the "what" and the workflow is the "how". Include a cross-link to [Agent Anatomy](/contributing/agent-anatomy) when explaining that commands spawn agents via the Task tool.
5. **Walkthrough Example** — Use `plan-phase.md` as a detailed walkthrough. Show its frontmatter, explain each section, trace how it spawns the vit-planner agent, and what artifacts it produces (PLAN.md files).
6. **Registration** — How new commands become available. Explain the file-based registration system (placing the file in the right directory makes it available).
7. **Checklist** — End with a checklist: "To create a new command, you need: [frontmatter], [process steps], [workflow reference if needed], [agent spawning if needed]."

**Agent Anatomy (DOCS-06) — `docs/contributing/agent-anatomy.md`:**

- `files/agents/vit-planner.md` (use as walkthrough example)
- `files/agents/vit-executor.md` (execution agent)
- `files/agents/vit-verifier.md` (verification agent)
- Several other agent files to identify common patterns

Write a comprehensive guide covering:
1. **File Location** — Agents live in `files/agents/`. The filename is the agent identifier (e.g., `vit-planner.md`).
2. **Frontmatter** — Document frontmatter fields: `name`, `description`, `tools` (list of available tools), `color` (terminal output color). Show a complete example.
3. **System Prompt Structure** — Agents use XML sections to structure their system prompt: `<role>`, `<philosophy>`, `<execution_flow>`, `<success_criteria>`, etc. Explain how these sections shape agent behavior.
4. **Task() Spawning** — How commands spawn agents using the Task tool. The command passes context to the agent as a task description. Show the spawning pattern.
5. **subagent_type Mapping** — Explain how `model_profile` in config maps agent names to Claude model tiers. The `subagent_type` field in the Task() call determines which model runs the agent.
6. **Walkthrough Example** — Use `vit-planner.md` as a detailed walkthrough. Show its role definition, key sections (philosophy, task_breakdown, goal_backward, plan_format), and how it receives context from the plan-phase command.
7. **Checklist** — End with a checklist: "To create a new agent, you need: [frontmatter], [role section], [execution flow], [success criteria], [model profile mapping]."
