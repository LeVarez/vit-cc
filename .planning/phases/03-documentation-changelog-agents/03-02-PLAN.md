  <action>
  Create `.claude/agents/vit-changelog-writer.md` with the following structure:

  **Frontmatter:**
  ```yaml
  ---
  name: vit-changelog-writer
  description: Writes versioned CHANGELOG entry at milestone completion and updates all project documentation. Spawned by complete-milestone before the archive step. Reads all phase SUMMARY.md files to generate the entry.
  tools: Read, Write, Edit, Bash, Glob, Grep
  color: blue
  ---
  ```

  **Role section:**
  State that this agent writes a versioned CHANGELOG entry and updates all project documentation when a milestone is completed. It is spawned by complete-milestone and receives VERSION, MILESTONE, WORK_DIR, and the phases directory path in its prompt context.

  The agent performs two operations:
  1. Promotes the [Unreleased] CHANGELOG section to a versioned entry `## [VERSION] - DATE` and adds a fresh empty `## [Unreleased]` above it
  2. Updates all project documentation (README.md, docs/) with a comprehensive summary of what the milestone delivered

  IMPORTANT CONSTRAINTS:
  - MUST use Edit tool for targeted section replacement in existing docs, NEVER Write tool for full file overwrites of existing files
  - MUST consume (clear) the [Unreleased] section content when promoting to versioned entry
  - MUST add a fresh empty `## [Unreleased]` section after promotion
  - Non-blocking — all failures log one line and continue
  - MUST commit all doc/changelog changes before returning

  **Execution flow with these steps:**

  **Step 1: Parse context from prompt.**
  Extract from the prompt context provided by complete-milestone:
  - `VERSION` — the version being released (e.g., `1.0`)
  - `MILESTONE` — milestone identifier (e.g., `v1.0`)
  - `WORK_DIR` — absolute path to the working directory
  - `PHASES_DIR` — path to phases directory (e.g., `$WORK_DIR/.planning/phases/`)

  **Step 2: Read all phase SUMMARY.md files in the milestone.**
  ```bash
  # Find all SUMMARY.md files across all phases
  ls "$PHASES_DIR"/*/*-SUMMARY.md 2>/dev/null
  ```

  Read each SUMMARY.md to extract:
  - Phase number and name
  - Key accomplishments (from Accomplishments section)
  - What was delivered (from provides/deliverables)
  - Any notable decisions or changes

  Build a comprehensive list of everything delivered in this milestone.

  **Step 3: Generate versioned CHANGELOG entry (DOC-05, DOC-06).**

  Categorize all accomplishments into Keep a Changelog categories:
  - `### Added` — new features, new commands, new agents, new capabilities
  - `### Changed` — modifications to existing behavior
  - `### Fixed` — bug fixes
  - `### Removed` — removed features (rare)

  Format the versioned entry:
  ```markdown
  ## [VERSION] - YYYY-MM-DD

  ### Added
  - Phase N (Phase Name): one-liner describing what was added
  - Phase M (Phase Name): one-liner describing what was added

  ### Changed
  - Phase N (Phase Name): one-liner describing what changed (if applicable)

  ### Fixed
  - Phase N (Phase Name): one-liner describing what was fixed (if applicable)
  ```

  Only include category subsections that have entries. Do not include empty subsections.

  **Step 4: Write the versioned CHANGELOG entry.**

  Check if CHANGELOG.md exists:
  ```bash
  ls "$WORK_DIR/CHANGELOG.md" 2>/dev/null
  ```

  **If CHANGELOG.md does NOT exist:** Create it with the standard header and the versioned entry directly:
  ```markdown
  # Changelog

  All notable changes to this project will be documented in this file.

  The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
  and this project adheres to [Semantic Versioning](https://semver.org/).

  ## [Unreleased]

  ## [VERSION] - YYYY-MM-DD

  ### Added
  - ...
  ```

  **If CHANGELOG.md exists with `## [Unreleased]`:**

  Two-step atomic operation:
  1. **Replace** the [Unreleased] section content with the versioned entry. The [Unreleased] content is consumed — moved into the versioned entry. The resulting structure is:
     ```markdown
     ## [Unreleased]

     ## [VERSION] - YYYY-MM-DD

     ### Added
     - ... (content from [Unreleased] MERGED with content from SUMMARY.md files)
     ```

  2. Ensure the `## [Unreleased]` section is now **empty** (just the heading followed by a blank line, then the versioned entry below).

  Use the Edit tool to perform this replacement.

  CRITICAL: The versioned entry should include BOTH:
  - Content that was already in [Unreleased] (accumulated from doc-updater per-phase runs)
  - Any additional accomplishments from SUMMARY.md files that weren't in [Unreleased]

  This handles the case where some phases ran before doc-updater was installed.

  **Step 5: Update project documentation (README.md, docs/) (DOC-06).**

  Read all phase SUMMARY.md files again and update project documentation with a comprehensive view of the milestone.

  For README.md:
  1. Read the full file
  2. Identify sections by heading (`grep -n "^## " "$WORK_DIR/README.md"`)
  3. For each section that relates to milestone accomplishments:
     - Use Edit tool for targeted section updates
     - MERGE new information with existing content
     - PRESERVE all manually-written content

  For docs/ directory (if exists):
  ```bash
  ls "$WORK_DIR/docs/" 2>/dev/null
  ```
  If docs/ exists, apply the same section-identification and targeted-update approach to relevant files.

  The scope of documentation updates is broader than doc-updater (which handles one phase at a time). The changelog-writer updates docs with a holistic view of the entire milestone — cross-referencing all phases to create coherent documentation.

  **Step 6: Commit all changes.**
  ```bash
  cd "$WORK_DIR" && git add CHANGELOG.md README.md docs/ 2>/dev/null
  cd "$WORK_DIR" && git diff --cached --quiet || git commit -m "docs: update documentation and changelog for v${VERSION}"
  ```

  Only commit if there are staged changes.

  **Step 7: Log completion.**
  Log: `[changelog-writer] Versioned CHANGELOG entry [${VERSION}] created, {N} documentation files updated`

  **Error handling throughout:**
  - If any SUMMARY.md file is unreadable, skip it and continue with others
  - If CHANGELOG update fails, log `[changelog-writer: CHANGELOG update failed — continuing]`
  - If documentation update fails, log `[changelog-writer: doc update failed — continuing]`
  - If git commit fails, log `[changelog-writer: commit failed — continuing]`
  - The agent MUST NEVER cause complete-milestone to abort

  **What NOT to include:**
  - Do NOT overwrite entire documentation files — use Edit for section replacement
  - Do NOT leave [Unreleased] content in place after promotion (it must be consumed)
  - Do NOT modify SUMMARY.md, PLAN.md, STATE.md, or ROADMAP.md
  - Do NOT archive or delete any files — that is complete-milestone's job
  - Do NOT duplicate content already in versioned CHANGELOG entries
  </action>
