  <action>
  Create `.claude/agents/vit-doc-updater.md` with the following structure:

  **Frontmatter:**
  ```yaml
  ---
  name: vit-doc-updater
  description: Updates targeted documentation sections after a phase completes. Spawned by execute-phase after all waves pass verification. Reads SUMMARY.md and PLAN.md to identify which docs/sections to update.
  tools: Read, Write, Edit, Bash, Glob, Grep
  color: green
  ---
  ```

  **Role section:**
  State that this agent updates project documentation after a phase completes. It is spawned by execute-phase and receives PHASE_NUM, PHASE_NAME, PHASE_DIR, WORK_DIR, and MILESTONE in its prompt context. The agent performs two types of updates:
  1. Section-scoped updates to documentation files (README.md, docs/) based on what the phase built
  2. Appending a new entry to the [Unreleased] section of CHANGELOG.md

  IMPORTANT CONSTRAINTS:
  - MUST use Edit tool for targeted section replacement, NEVER Write tool for full file overwrites of existing files
  - MUST preserve all existing content outside targeted sections verbatim
  - MUST NOT touch versioned CHANGELOG entries (only [Unreleased])
  - Non-blocking — all failures log one line and continue
  - MUST commit doc changes before returning

  **Execution flow with these steps:**

  **Step 1: Parse context from prompt.**
  Extract from the prompt context provided by execute-phase:
  - `PHASE_NUM` — phase number
  - `PHASE_NAME` — phase name
  - `PHASE_DIR` — path to the phase directory (e.g., `.planning/phases/03-documentation-changelog-agents`)
  - `WORK_DIR` — absolute path to the working directory
  - `MILESTONE` — milestone identifier (e.g., `v1.0`)

  **Step 2: Read phase artifacts to determine what was built.**
  ```bash
  # Read all SUMMARY.md files for this phase
  cat "$WORK_DIR/$PHASE_DIR"/*-SUMMARY.md 2>/dev/null

  # Read all PLAN.md files for files_modified lists
  grep "^files_modified:" "$WORK_DIR/$PHASE_DIR"/*-PLAN.md 2>/dev/null
  ```

  From SUMMARY.md `Accomplishments` section and PLAN.md `files_modified` lists, build a list of what was delivered and which files were touched. This determines which documentation sections need updating.

  **Step 3: Determine which documentation sections to update (DOC-02, DOC-04).**

  Use this semantic mapping heuristic — the agent (Claude) reads the accomplishments and maps them to documentation sections:

  - New or modified command in `.claude/commands/vit/*.md` -> update "Commands" or "Commands reference" section in README.md
  - New agent in `.claude/agents/*.md` -> update "Agents" or "Agents reference" section in README.md
  - New workflow step or behavior change -> update relevant workflow documentation (if docs/ exists)
  - New configuration option -> update "Configuration" section
  - Internal changes only (templates, planning docs) -> no README update needed, but still append to CHANGELOG

  The agent MUST check if each target section heading exists in the file using:
  ```bash
  grep -n "^## " "$WORK_DIR/README.md" 2>/dev/null
  ```

  If a relevant section does not exist in the file, the agent should either:
  - Append a new section at an appropriate location, OR
  - Skip the update if the change is not user-facing

  **Step 4: Update documentation files using section-scoped editing.**

  For each identified section to update:
  1. Read the full target file (e.g., README.md)
  2. Locate the section by its heading (e.g., `## Commands reference`)
  3. Determine the section boundary (from heading to next heading of same or higher level)
  4. Read existing section content — MERGE new information with existing content, do not replace wholesale
  5. Use the **Edit tool** to replace only the section content. NEVER use Write to overwrite the entire file.

  If `docs/` directory exists, also check for and update relevant files there using the same approach.

  **Step 5: Update CHANGELOG.md with [Unreleased] entry (DOC-04).**

  First, check if CHANGELOG.md exists:
  ```bash
  ls "$WORK_DIR/CHANGELOG.md" 2>/dev/null
  ```

  **If CHANGELOG.md does NOT exist:** Create it with the standard Keep a Changelog 1.1.0 header:
  ```markdown
  # Changelog

  All notable changes to this project will be documented in this file.

  The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
  and this project adheres to [Semantic Versioning](https://semver.org/).

  ## [Unreleased]

  ### Added
  - Phase {PHASE_NUM} ({PHASE_NAME}): {one-liner from SUMMARY.md accomplishments}
  ```

  **If CHANGELOG.md exists:** Find the `## [Unreleased]` section:
  ```bash
  grep -n "^## \[Unreleased\]" "$WORK_DIR/CHANGELOG.md" 2>/dev/null
  ```

  If `## [Unreleased]` exists:
  - Find the `### Added` subsection within it
  - If `### Added` exists: append the new bullet to it (do NOT create a duplicate `### Added`)
  - If `### Added` does not exist: add `### Added` with the new bullet immediately after `## [Unreleased]`
  - Use the Edit tool for this targeted insertion

  If `## [Unreleased]` does not exist: insert `## [Unreleased]` section at the top of the file (after the header), then add the entry.

  The entry format for each phase:
  ```
  - Phase {PHASE_NUM} ({PHASE_NAME}): {one-liner summarizing what was built, from SUMMARY.md}
  ```

  Also categorize changes appropriately — use `### Changed`, `### Fixed`, `### Removed` subsections if the phase work includes those types of changes (not just `### Added`).

  CRITICAL: NEVER touch any content below the [Unreleased] section. Versioned entries (`## [X.Y] - DATE`) are immutable.

  **Step 6: Commit documentation changes.**
  ```bash
  cd "$WORK_DIR" && git add CHANGELOG.md README.md docs/ 2>/dev/null
  cd "$WORK_DIR" && git diff --cached --quiet || git commit -m "docs(phase-${PHASE_NUM}): update documentation and changelog"
  ```

  Only commit if there are staged changes. If no documentation was updated (all changes were internal), skip the commit.

  **Step 7: Log completion.**
  Log: `[doc-updater] Updated {N} documentation sections, CHANGELOG [Unreleased] entry added for Phase {PHASE_NUM}`

  If no documentation sections were updated (only CHANGELOG): log `[doc-updater] No user-facing doc sections updated; CHANGELOG [Unreleased] entry added for Phase {PHASE_NUM}`

  **Error handling throughout:**
  - If any file read/write fails, log one line and continue to the next file
  - If CHANGELOG update fails, log `[doc-updater: CHANGELOG update failed — continuing]` and continue
  - If git commit fails, log `[doc-updater: commit failed — continuing]` and continue
  - The agent MUST NEVER cause execute-phase to abort

  **What NOT to include:**
  - Do NOT overwrite entire files — always use Edit for targeted section replacement
  - Do NOT modify versioned CHANGELOG entries (anything below [Unreleased])
  - Do NOT require a configuration file or section mapping from the user
  - Do NOT modify SUMMARY.md, PLAN.md, STATE.md, or ROADMAP.md — those are owned by other workflows
  - Do NOT update documentation for internal-only changes (templates, planning docs) unless they affect user-facing behavior
