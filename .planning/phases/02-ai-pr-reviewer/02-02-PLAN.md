  <files>

  <action>
  In the verify-work command (`.claude/commands/vit/verify-work.md` and `files/commands/vit/verify-work.md`), add a step **8.6** immediately after step 8.5 (Promote PR — Route A only).

  Step 8.6 spawns the reviewer INSIDE the Route A gate, and ONLY when PR_PROMOTED=true.

  Add this step:

  ```
  8.6. **Spawn AI reviewer — Route A only** (after successful promotion)

     Gate: Only runs when `PR_PROMOTED=true` (step 8.5 succeeded). If PR promotion was skipped (Routes B/C/D), or failed, or gh was unavailable — skip this step entirely.

     ```bash
     # Get repo slug for reviewer context
     REPO=$(cd "$WORK_DIR" && gh repo view --json nameWithOwner --jq '.nameWithOwner' 2>/dev/null || echo "")
     ```

     If `REPO` is empty: log `[reviewer skipped — could not determine repo]`, continue.

     Spawn vit-pr-reviewer:
     ```
     Task(
       prompt="""
     <context>
     PR Number: {PR_NUM}
     Repo: {REPO}
     Working Directory: {WORK_DIR}
     Phase Number: {PHASE_NUM}
     Phase Name: {PHASE_NAME}
     </context>

     Review this PR and post severity-tiered findings (block-merge / should-fix / nit) as a GitHub review comment, plus up to 5 inline diff comments on specific changed lines.
     """,
       subagent_type="vit-pr-reviewer",
       model="{reviewer_model}",
       description="AI review of PR #{PR_NUM}"
     ) || log "[reviewer failed — continuing]"
     ```

     The `{reviewer_model}` comes from the model lookup table (resolved in the workflow's resolve_model_profile step). In the command file, reference it as the model resolved for vit-pr-reviewer.

     If the Task call fails or the agent crashes: log `[reviewer failed — continuing]` and proceed to step 9. The reviewer is non-blocking — it must NEVER prevent verify-work from completing.
  ```

  **Placement:** After step 8.5 (Promote PR), before step 9 (diagnose issues). The step must be clearly nested inside the Route A gate — it only runs when PR_PROMOTED=true.

  **Error handling:** The `|| log` pattern after the Task call ensures reviewer crashes don't abort verify-work. This matches the non-blocking pattern used for PR promotion itself.

  IMPORTANT: Both `.claude/` and `files/` copies must be exactly identical after edits.
  </action>
