# Testing Practices

**Analysis Date:** 2026-03-18

## Framework

**Test Runner:** Vitest
- Configured in `package.json` (scripts section)
- Runs via `npx vitest run tests/phases/`
- Dual reporter: JSON output (`results.json`) + verbose text (`results.txt`)

**Language:** TypeScript (`.test.ts` files in target projects)
- VIT itself has no tests — it's a framework that generates tests for target projects
- Tests generated by `vit-test-writer` agent per phase

## Test Structure

**Location Pattern:**
```
tests/
└── phases/
    ├── results.json          # Machine-readable test results (CI parsing)
    ├── results.txt           # Human-readable verbose output
    └── v1.6.0/                 # Milestone-scoped test directories (new)
        └── phase-01.test.ts
    # OR legacy layout:
    └── phase-01.test.ts
```

**CI Detection Logic:**
- If `tests/phases/` exists AND contains `*.test.ts` → run tests
- Otherwise → skip (output `has_tests=false`)
- Supports both milestone-scoped (`tests/phases/v1.6.0/`) and legacy (`tests/phases/`) layouts

## Generated Tests

**When Generated:** After phase execution (by `vit-test-writer` agent)

**Input to Generator:**
- Phase PLAN.md `must_haves` section
- Phase SUMMARY.md with what was built
- Existing codebase context

**Test Conventions (Generated):**
- File naming: `phase-NN.test.ts` or feature-scoped name
- Describe blocks match phase/feature names
- Tests are end-to-end or integration style (verify observable behavior)
- Focus on must-haves from phase plan

## CI Integration

**Trigger:** Push to `feature/**`, `milestone/**`, `quick/**` branches

**Workflow (`files/github/workflows/phase-ci.yml`):**
1. Run Vitest with JSON + verbose reporters
2. Parse `results.json` for counts (total/passed/failed)
3. Extract phase/milestone context from branch name
4. Read issue number from `.planning/STATE.md`
5. Post formatted comment to linked GitHub issue
6. Exit with code 1 if any tests failed

**Comment Format on GitHub Issue:**
- Pass: `✅ Phase tests passed (N/N)`
- Fail: `❌ Phase tests failed (N/N passed, M failed)` + failure details

## No Tests in VIT Itself

This repository (vit-cc / vit-claude) distributes a framework — it does not have its own test suite. Tests exist in target projects that install VIT.

**What the CI workflow tests:** Phase implementation in target projects, not VIT framework code.
